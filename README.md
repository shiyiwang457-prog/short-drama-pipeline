# 短剧生产三环流水线

> 给 Claude Code 装上「会拍戏」的能力：看剧本 → 拆分镜 → 写 AI 视频提示词。
> 能力不在模型脑子里，在这个仓库的**文件**里。

---

## 这是什么

一套 Claude Code skill ＋ 一个书证知识库，把**影视表演与构图的书本规则**变成**AI 视频提示词的可执行约束**。

它解决的问题很具体：AI 视频提示词写起来像玄学——「氛围感」「电影感」「情绪到位」这类词，模型读不懂，写了等于没写。这套东西把它们换成**书上有出处、脚本能检查**的具体指令。

举三个真实例子：

| 原来会这么写 | 现在会这么写 | 依据 |
|---|---|---|
| 画面里的一切保持静止 | 【这12秒里一直在动的东西】蜡烛火苗轻微摇曳；红点每2秒闪一次<br>【一直不动的东西】桌子、玻璃杯、家具 | 写「一切静止」会让**火苗也冻住**（实测） |
| 单一暖光源在画外左上 | 暖色的光从画面左上方斜射进来，方位角约135度<br>影子从光源正下方那点向外发散 | 给带量词的名词，模型**把光源画成一支蜡烛摆上茶几**（实测） |
| 她很伤心 | **受控**：眉毛平，嘴角停在刚落下的位置<br>**不受控**：眼尾笑过的纹退得比嘴角慢；手不再往外指 | BODY-35：换个性格的人来演，这段描述要不要改？不用改＝只写了「做什么」 |

## 三环怎么咬合

```
   念头 / 本子
       │
  ┌────▼─────────┐
  │ story-doctor │  故事层 ── 这个故事打不打动人
  └────┬─────────┘         产出：定稿台本
       │
  ┌────▼─────────┐
  │  storyboard  │  分镜层 ── 这场戏怎么拍
  └────┬─────────┘         产出：分镜表
       │
  ┌────▼──────────────┐
  │  prompt-assembly  │  装配层 ── 翻译成平台吃的文本
  └────┬──────────────┘      产出：可直接粘贴的提示词
       │
   AI 视频平台 → 回看 → 回填实测
```

**三条边界是硬的**：构图判断归分镜层，措辞与平台语法归装配层。
判据：*提示词里出现了分镜表没有的构图判断 ＝ 回写分镜表，不是就地发明。*

```bash
bash install.sh
```

规则库装到 `~/Desktop/11/_规则库/`。仓库在别处的话：

```bash
bash install.sh ~/Documents/我的仓库
```

脚本会自动改掉 skill 里写死的路径，并**用样例真跑一遍门禁**——看到「✅ 十道门禁全绿」才算装成。

⚠️ 装完开新窗口，当前窗口不加载新 skill。

## 交付格式 v6（当前）

一段剧情 ＝ 一个可直接复制的纯文本框：

```text
场景={{Image 1}} 女孩={{Image 女孩参考图}} 男孩={{Image 男孩参考图}}

真人电影风格,画面不要出现任何文字，生成视频无BGM；16:9，客观第三视角，固定机位。
场景严格参考{{Image 1}}：<空间逐项枚举>。<风格／色调／胶片／光>。<本段专属约束>。

c01,4s,(空间:…)(姿态:角色-动作)(位置:主体-画面位置)(情绪:角色-情绪词 6/10) <景别＋机位延续声明>。<连续动作，拐点分明，写到部件级>。<角色>用中文<语气>地说道<台词>
c02,…
只保留<音效白名单>，不加入旁白或音乐。【不出现任何文字字幕】
```

**跳过规则**：某字段当下没有描述就整行跳过——跳过，不发明。

## 十一道门禁（脚本能跑）

```bash
python3 skills/prompt-assembly/tools/check_gates.py 你的提示词表.md
python3 skills/prompt-assembly/tools/check_props.py 你的提示词表.md
```

| 门禁 | 治什么 |
|---|---|
| **负向词 = 0** | 平台官方：写了负向词模型忽略；更坏的是「不要抓衣角」被读成「抓衣角」 |
| 偷懒面部 | 「脸保持原样」这类等于没写 |
| 缺【镜头视角】 | 谁在拍 · 机位动不动 · **被拍的人知不知道** |
| 缺运动元素清单 | ⭐ 治「一切静止」把火苗一起冻住 |
| 配额合计 ≠ 块长 | 逐块对账 |
| **单一景别 ≥6 秒** | 模型在长单一景别下明显变差 |
| **物件流转** | 一手持两物 / 凭空出现 / 悬空 / 容器倒进拿着它的手 |

两条豁免都**可判定**，不靠人记：无人脸块＝控制词里零个面部部件；4″ 单镜＝已是平台下限。

## 知识库：117 张书证卡

每张卡 = **一条规则 ＋ 出处页码 ＋ 它会怎么失效**：

```yaml
id: BODY-35
型: 构成型                      # 必须/禁止/构成/时序/映射/量化 六型之一
核心规则证据档: A               # A直引 / B转述 / C推论 / D无书本依据
出处页: [121]                   # 🔴 可回查
站点: [站6-可见状态, 站0-形体卡]
适用景别: [全部]                # ⚠️ 用卡前必核
推论字段: [适用景别]            # 哪些筛选值是推的，不是书上写的
失败模式: 只见特征不见其人       # 质检清单从这里自动派生
实测: 待测                      # 生成回看后回填
```

**三个设计要点**：

1. **出处页码必须留** —— 卡是二手的，书是一手的，任何时候可以回去核
2. **「失败模式」是卡的一半** —— 只写「该怎么做」是废卡，省事的是「这么做会怎么砸」
3. **适用条件必须核** —— 实证：`FRAME-43 用眼睛高度差表现权力关系` 的原始语境是**警长抓逃犯**，套到恋人托付的戏上，画面会读成「他在压她」。**卡没错，是没读适用条件**

### 两套证据分级，不通用

| | 分级 | 含义 |
|---|---|---|
| 书证卡 | A / B / C / D | 书上写死的 → 推导出来的 |
| 模型档案 | 官A / 官B / 实C / 推D | 厂商文档 → 实测 → 推测 |

⚠️ 混用这两套 ＝ 把猜测当书证。

## 平台实测数据（Seedance 2.5，2026-08）

| 实测 | 数字 | 影响 |
|---|---|---|
| ⭐ **模型对「静」慷慨、对「动」吝啬** | 6.08 秒成片里**只有 1.71 秒有动作** | 必须写「**占满整整 X 秒**」 |
| 时长 | 单块 4–30 秒 | 4 秒是下限，切不出更短的镜头 |
| 画幅 | `--ratio` 无效 | 要在界面设，行内参数是摆设 |
| 时间戳 | 是「时间预算」不是逐帧剪辑点 | 允许小幅漂移 |

⚠️ **换平台或平台改版，这份要重测。** skill 的站 0 是硬门禁，会拦住没填参数就开工。

仓库里有装配日志机制（`_装配日志.jsonl` ＋ Stop hook 核查）来推动回填，但**闭环转不转取决于使用者是否把生成结果贴回来**。

如果你用了这套东西并跑出了结果，欢迎开 issue 告诉我们哪条规则**没生效**——那比再抽十张卡有价值。
