# 三环流水线 · 架构说明

> 为什么是三个 skill 而不是一个，以及知识库为什么长这样

---

## 一 · 三环怎么咬合

```
   念头 / 本子
       │
  ┌────▼─────────┐
  │ story-doctor │  故事层 ── 这个故事打不打动人
  └────┬─────────┘         产出：定稿台本
       │
  ┌────▼─────────┐
  │  storyboard  │  分镜层 ── 这场戏怎么拍
  └────┬─────────┘         产出：分镜表（构图与表演判断已定）
       │
  ┌────▼──────────────┐
  │  prompt-assembly  │  装配层 ── 翻译成平台吃的文本
  └────┬──────────────┘      产出：可直接粘贴的提示词
       │
   AI 视频平台 → 回看 → 回填实测
```

### ⭐ 为什么必须分三层

**每一层只做一件事，越界就是 bug。** 三条边界是硬的：

| 谁的活 | 归哪一层 | 越界的后果 |
|---|---|---|
| 故事好不好、人物立不立得住 | story-doctor | — |
| 景别 · 机位 · 焦距 · 光位 · 轴线 · 静止清单 · 块划分 | **storyboard** | 🔴 决策绕过导演审阅 |
| 措辞 · 括号语法 · 时间轴 · 平台参数 | **prompt-assembly** | 🔴 分镜表和提示词不同步 |

**判据（可执行）**：
> 提示词里出现了分镜表没有的构图判断 ＝ **回写分镜表**，不是就地发明。

这不是洁癖。实证（《纪念日》2026-08-13）：构图决策被直接写进提示词 v3，分镜表还停在「固定·标准」×11 —— **后果不只是不同步，是那些决策绕过了人的审阅**。

## 二 · 知识库为什么长这样

### 一张卡 = 一条规则 ＋ 它的出处 ＋ 它会怎么失效

```yaml
id: BODY-35
核心规则证据档: A                     # A/B/C/D 四档
出处书: ["侯寄南《演员的形体动作和形象创造》"]
出处页: [121]                        # 🔴 可回查
站点: [站6-可见状态, 站0-形体卡]      # 哪一站用得上
适用景别: [全部]                     # ⚠️ 用卡前必核
表演风格档: [自然主义, 戏剧化, ...]
失败模式: 只见特征不见其人            # 质检清单从这里派生
实测: 待测                           # 生成回看后回填
跨书印证: [...]                      # 别的书怎么说同一件事
相关: ["[[BODY-32 ...]]"]
```

**三个设计要点**：

**① 出处页码必须留。** 卡是二手的，书是一手的。任何时候可以回去核。

**② 「失败模式」是卡的一半。** 只写「该怎么做」的卡是废卡——真正省事的是「这么做会怎么砸」。全库 100+ 条失败模式派生成 `_质检清单.md`，按站分组，每站作业完逐条比对。

**③ 「适用条件」必须核。** 实证：`FRAME-43 用眼睛高度差表现权力关系` 的原始语境是**警长抓逃犯**。套到**恋人托付**的戏上，画面会读成「他在压她」。**卡没错，是没读适用条件。**

### 两套证据分级，不通用

| | 分级 | 意思 |
|---|---|---|
| **书证卡** | A / B / C / D | 书上写死的 → 推导出来的 |
| **模型档案** | 官A / 官B / 实C / 推D | 厂商文档 → 我们实测 → 推测 |

⚠️ **混用这两套 = 把猜测当书证。**

## 三 · 门禁：让"忘了做"变成"跑不过去"

### 分镜层的门禁

| 站 | 门禁 |
|---|---|
| 站 −1 全片通读 | `ls` 得出《全片约束表》才准进站 0 |
| 站 1 场景卡 | **每场一张**，跳场就是断裂 |
| 站 7 出审阅版 | 必含「明知而不做」——考虑过但放弃的手法 ＋ 理由 |

**实证**：只读了场 2 与场 16 就定了九个构图决策，通读全片后**三个关键决策里错了两个**。

### 装配层的门禁（脚本可跑）

```bash
python3 ~/.claude/skills/prompt-assembly/tools/check_gates.py  <提示词表.md>
python3 ~/.claude/skills/prompt-assembly/tools/check_props.py  <提示词表.md>
```

| # | 门禁 | 为什么 |
|---|---|---|
| 1 | **负向词 0** | Seedance 官方：写了负向词模型忽略；更坏的是**「不要抓衣角」被读成「抓衣角」** |
| 2 | 偷懒面部 0 | 「脸保持原样」这类，等于没写 |
| 3 | 缺【镜头视角】0 | 谁在拍 · 机位动不动 · **被拍的人知不知道** |
| 4 | 缺【光与脸】0 | 无人脸块豁免（判据：控制词里一个面部部件都没有） |
| 5 | 缺运动元素清单 0 | ⭐ 治「画面一切静止」——那句话会把火苗一起冻住 |
| 6 | 缺镜头配额 0 | 4 秒单镜豁免（已是平台下限） |
| 7 | 音频为空 0 | |
| 8 | 配额合计 = 块长 | 逐块对账 |
| 9 | 镜号连续且在行首 | 治「标记夹在正文中间」 |
| 10 | 单一景别 < 6 秒 | ⭐ 模型在长单一景别下表现明显变差 |
| 11 | 物件流转 | 一手持两物 / 凭空出现 / 悬空 / 容器倒进拿着它的手 |

⭐ **两条豁免都是可判定的，不靠人记。**

### ⚠️ 写门禁本身的教训

**判据宁窄勿宽。** 曾把负向词从 5 个词扩到 9 个（加了「不能｜无｜不会｜别」），12 处命中**全是假阳性**——「景**别**」「**别**处」「差**别**」「**无**人称」。

**统计脚本先自证再下判定**：
- 「时间轴 21/25 块没写」→ 正则只认整数秒，漏了 `1.2-2.5秒` → 真实只有 5 块
- 「块数 25」→ 场 8 的编号是 `🔟`（单字符），不在 `[0-9️⃣]` 里 → 从第一版起一直漏

**块数/总数对不上人工清点 ＝ 脚本有洞，它报的一切都不可信。**

## 四 · 装配层的六条实战经验

从《纪念日》v1→v7 打出来的，换项目也成立：

**① 不许写「画面里的一切保持静止」。**
改成两行显式清单：这 N 秒里**一直在动的** ／ **一直不动的**。
> 原本想表达「结束了」，写成「一切静止」是**把世界一起关掉**；
> 写成「**房间还在动，只有她停住了**」，才是「她一个人停在那儿」。

**② 别给模型带量词的名词。**
「单一暖**光源**在画外」→ 它把光源实体化成一支蜡烛摆上茶几。
改成「暖色的光从画面左上方斜射进来」——**去掉名词，只留效果**。

**③ 时长是配额，不是坐标。**
- `镜头1（0-1.5秒）` ＝ 坐标 → 会挤压
- `【镜头1：中景 1.5秒】` ＋「**占满整整 1.5 秒**」＝ 配额

⭐ 实测：模型**对「静」慷慨、对「动」吝啬**——6.08 秒里只有 1.71 秒有动作。给足时间它会把富余填成静止，所以「占满」这个词必须写。

**④ 景别标签必须配得上内容。**
中景里写「瞳孔跟着收缩一次」＝ 这场戏白写，中景根本看不见瞳孔。
反过来，远景里的面部要按 BODY-40 **缩放幅度**：基调（整张脸一起动）保留，细部（鼻梁起皱）换成远景看得见的（头往后仰、肩膀跟着抖）。

**⑤ 固定机位也能有景别变化——让人物自己前后移动。**
场 3 是「她忘了关机器」，机位不能动，但 16 秒单一景别模型做不好。
解法不是改机位，是**她前倾吃药时变大，靠回椅背时变回去，凑近关机时最大**。⭐ 机位真的一帧没动，叙事设定完好。

**⑥ 演技写三层，不是写形容词。**

```
意图    这个人此刻在做的事
受控    哪些部件被他压住了
不受控  哪里在漏（瞳孔对焦 / 吞咽 / 呼吸变深 / 手指收紧 / 眼眶）
```

判据（BODY-35）：**把这个人换成另一个性格的人，这段描述要不要改？不用改 ＝ 只写了「做什么」。**

## 五 · 已知的洞

**① 音频是 0 张卡。** 18 本书里没有一本讲声音设计。音频段目前全是工程判断。

**② 摄影用光也曾是 0 张卡**，后来补扫了 Framed 系列才有 FRAME-45～50。**规则库有洞是常态，重点是知道洞在哪。**

**③ 平台参数会过期。** `_模型档案-Seedance.md` 是 2026-08 实测的。换平台或平台改版，站 0 会拦住。

**④ 实测回填还很少。** 大部分卡的 `实测:` 字段是「待测」。生成回看之后要回填 `服从 / 部分 / 无效`——**这是这套系统唯一能真正长本事的地方**。
