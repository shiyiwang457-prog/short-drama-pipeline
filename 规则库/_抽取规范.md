# 规则卡 · 抽取规范 v0.6

> 2026-08-13 立。适用于从 `<原书正文·本地扫描件，未随仓库分发>` 的全书 OCR 文本中抽取规则卡。

---

## 一、什么算一条「规则」

**判据：能不能变成一个可执行的判断或约束。**

书上的内容分三类，**只有一类能成卡**：

| 类 | 例（侯寄南第四讲） | 处理 |
|---|---|---|
| **原理／解释** | 「肌肉收缩前适当的拉长，收缩时产生的力量就更大」 | ❌ 不成卡（生理学解释） |
| **规则** | 「如果缺少动作前的反动作……就会使形体动作机械、笨拙、僵死」 | ✅ **成卡** |
| **例证** | 「要劈开一个树根，就要先把斧头举起」 | ❌ 不成卡，**附在卡上作证据** |

## 二、规则必须是这六型之一（v0.2 由四型扩为六型）

套不进六型的，就不是规则，是原理或例证。

| 型 | 形态 | 例 |
|---|---|---|
| **必须型** | X 情况下必须有 Y | 用力动作前必须有反向预备 |
| **禁止型** | X 情况下不许 Y | 近景中动作不得大到出画 |
| **构成型** | X 由 a＋b＋c 构成 | 笑容＝口形弯＋眼睛弯＋眉宇舒展 |
| **时序型** | 先 X 后 Y | 笑收尾：声先止，形后消 |
| **映射型** | X → Y | 俯拍 → 压抑 |
| **量化型** | X 越…，Y 越… | 动作越用力，预备幅度越大 |

> v0.1 只有四型，导致构成型卡（FACE-03）和时序型卡（FACE-02）被硬塞成"必须型"。

## 三、卡片格式 v0.3

**frontmatter**（可查询字段）＋ **正文四段固定**（可阅读内容）。

```yaml
---
id: BODY-27
型: 映射型                      # 六型之一
核心规则证据档: A               # A直引 / B转述 / C推论 / D无书本依据
出处书: ["侯寄南《…》"]          # ⭐ v0.3 改为列表——一条规则可有多个出处
出处章: ["第三讲 · …"]
出处页: [46, 47, 48]            # ⭐ 纯数字列表，可排序可定位
出处书页: [39, 40, 41]           # 印刷页（＝PDF 页 − 偏移）
出处文件: <原书正文·本地扫描件，未随仓库分发>
站点: [站2-人物基线, 站6-可见状态]
影响: [G2-①参与部件]
适用景别: [全景, 中景]
适用场景类型: []
适用媒介: []
表演风格档: [自然主义, 戏剧化]
推论字段: [适用景别]             # 哪些筛选字段是我推的，不是书上写的
可反用: false                   # ⭐ v0.3 新增
反用效果: <可反用时才写>
失败模式: <书上说的"这样就错了">
实测: 待测
跨书印证: []                    # ⭐ v0.4 新增，见下
相关: []
冲突:
来源批次: "[[pNNN-NNN]]"
---
## 规则
## 书上怎么说   ← 只放原文，全 A 档
## 我的判断     ← B/C/D，逐条标档 + 推理链
## 失败模式
```

### 为什么出处要用列表
同一条规则常在一本书里出现两次以上（[[BODY-26 松弛不是松懈]] 在 p.29 与 p.88 各说一遍），或散在多章（[[BODY-29 表里可以矛盾]] 跨 p.59 / p.80-81）。
v0.2 只能写成字符串 `"88（另见 29）"`——**页码查不了、排不了序**。v0.3 起写成 `[88, 29]`。

> 注意：这与纪律 3 不冲突。纪律 3 禁的是**跨书合并**，多出处指的是**同一本书内的多处印证**。

### 为什么要有「可反用」
[[BODY-25 基本法则可以反用]] 证明：**规则卡是常态描述，不是禁令。** 书明说心慌意乱时动作逻辑与顺序的混乱"恰好表现出神魂颠倒的心理状态"。
所以每张卡要能回答：**故意违反它会得到什么效果？** 有答案的标 `可反用: true` 并写 `反用效果`。

### 为什么要有「跨书印证」（v0.4）
纪律 3 禁止**跨书合并成一张卡**——这条不变。但由此产生一个盲区：当第二本书讲了同一件事时，**这个事实无处安放**，卡本身查不到自己有几本书支持。

苏彭成第九章两批一次触发 **7 处**跨书重合（拍摄非连续性／节奏性中断／舞台 vs 镜头／笑的真假／眼神泄露／表里矛盾／渲染不得过分），全部只能写在批次文件里。后果：skill 取 [[BODY-29 表里可以矛盾]] 时，不知道它有**两本书四处出处**支持，**置信度信息丢失**。

**格式**（列表，两种写法）：
```yaml
跨书印证:
  - "苏彭成 p.321 巴拉兹「脸上有不受意志控制的部分」→ [[FACE-11 脸上有不受意志控制的部分]]"   # 对方也成卡了
  - "苏彭成 p.301 影视拍摄的非连续性（未成卡）"                                    # 对方那段没成卡
```

> **纪律 10：跨书印证必须双向登记。** A 卡写了指向 B 卡的印证，B 卡必须写回 A。
> 由 `_重算索引.py` 做对称性检查，不对称会在索引里报出来。

> **注意区分**：`跨书印证` 只登记**不同书**之间的印证；同一本书的多处出处走 `出处页` 列表（v0.3）；同书不同规则的关联走 `相关`。
> 例：[[FACE-01 近景动作不得大到出画]] 与 [[FACE-05 小景别下故意即作假]] 同出苏彭成第九章 → 走 `相关`，不是跨书印证。

### 除了卡，还有两种容器
| 容器 | 装什么 | 现有 |
|---|---|---|
| **卡** `卡/` | 规则＋证据 | 32 张 |
| **范例** `案例/` | 完整的 G2 成品示范，用作 few-shot | [[CASE-01 用步态区分三个人物（《茶馆》）]] |
| **索引** `部件清单.md` | 书承认哪些部件可控、可不可见 | 五系 |

判据：**能套进六型的进卡；套不进但是现成的好示范，进范例；只回答"有哪些部件"的进索引。**

## 四、抽取流程

1. 按路由表定位章节（哪一站用哪本书哪一章）
2. 通读该章 OCR 正文
3. 逐段判断：原理／规则／例证
4. 规则句 → 套四型写成卡
5. 标证据档，附原文片段与页码
6. 标适用条件与产出影响

## 五、六条纪律（v0.3 由三条增至六条）

1. **一段原文可出多条卡**（侯寄南那一段出了 4 条）
2. **不许把推论标成 A/B**——书上没直说的，一律 C，并写明推理链
3. ⭐ **卡是单一出处的，不许合并两本书的内容成一条卡**
4. ⭐ **末页证据**：批次登记为「已扫」时必须写出本批**最后一页**讲什么。写不出＝没读完，不许标已扫。（防「假已扫」——终端输出被 `head` 截断后误登记）
5. ⭐ **同一主题第二次进积压 → 立刻成卡，不许再积压**。
   　理由：积压记在**按页码切的批次文件**里，同一主题跨批必然重复登记。「表里矛盾」在 p042/p060/p079 三批各登记一次，三次都没被认出是同一条，直到把 10 条积压摊平才发现。**复现即信号。**
6. ⭐ **读过但不用的，必须写进「已排除」并给理由**。
   　只有三种终态：**成卡 / 并入已有卡 / 已排除**。没有第四种。留着不判 = 下次扫到同一页重新纠结一遍。
7. ⭐ **`站点` 只标「直接约束该站产出内容」的站，不标「该站会用到它」的站。**
   　通用原则（适用于所有站的美学/方法准则）一律标 `站点: [通用]`，**不占任何具体站的计数**。
   　skill 每站取卡 = **该站标签的卡 ＋ 全部 `[通用]` 卡**。
   　理由：按"会用到"标，通用原则会挂满各站，把站点覆盖率撑虚。Framed Ink 第一批实测：站1 显示 5 张，实际只有 1 张真的规定场景卡该写什么。
   　⚠️ 原纪律 7、8、9 顺延为 8、9、10。

第 3 条最重要。跨书的综合（如「侯寄南给结构 ＋ 苏彭成给幅度上限」）是 **skill 运行时做的事**，不预先固化成卡——因为怎么组合取决于具体镜头（景别、场景类型、风格档）。**卡忠于书，综合归运行时。**

## 六、不适用的规则也要建卡

书上的规则若不适用于本流水线（如「舞台演出」专用），**仍要建卡并标明不适用**。
否则以后会有人重新纠结同一条，或者误用。见 `形体组.md` 的 BODY-04。

## 九、结构演化模型与收敛判据（2026-08-13 立）

### 模型：一边扫，一边被内容逼着改结构

v0.1 → v0.2 → v0.3 的**每一条**改动都由一条具体内容触发，没有一条是预先设计的：

| 触发内容 | 逼出来的改动 |
|---|---|
| FACE-02／FACE-03 塞不进四型 | 六型 |
| 卡内 A/B/C 混杂 | 正文四段固定 |
| [[BODY-26 松弛不是松懈]] 一书两处 | 出处改列表 |
| [[BODY-25 基本法则可以反用]] | `可反用` 字段 |
| 表里矛盾三批重复登记 | 纪律 5 |
| 《茶馆》三人步态套不进六型 | `案例/` 容器 |
| 机体觉不是情绪也不是关节 | 部件清单 系统五 |

**预先设计 schema 再开扫必然漏掉这些**——读到 BODY-25 之前，无从知道"规则可以反用"。

### 失效点：两类改动成本差一个数量级

| 层 | 迁移方式 | 代价 |
|---|---|---|
| **frontmatter 层** | 脚本批量改 | 秒级（32 张卡实测） |
| **正文结构层** | 逐张重写 | **脚本迁不了** |

v0.2 改正文四段时只有约 10 张卡，代价可忽略。**同样的改动发生在 500 张卡时是几十批返工。**

→ **纪律 8：结构升级优先做成 frontmatter 字段。确实要动正文四段结构的，越早越好。**

### 收敛判据

当前节奏：约每 2 批改一次结构（v0.2 在第 2–3 批，v0.3 在第 5 批）——**未收敛，继续改是正常的**。

> **纪律 9：连续 3 批不产生结构改动 → 判定结构收敛。**
> 收敛后再遇到装不下的内容，**一律进「已排除 · 待结构升级」挂起**，攒够一批统一升版，**不当场改结构**。

目的：前期让结构充分演化，后期保护已有的数百张卡不被反复迁移。

**收敛计数（每批登记时更新）**：v0.3 立于第 5 批 → 当前连续 0 批未改。

## ⏸ 待结构升级 #2：方法类卡没有验证方式（2026-08-13 登记）

**触发**：第一轮实测设计时发现，57 张卡里 8 张（BODY-04/28/33/37/38/39/42/43）**不由「模型服不服从」验证**——它们规定的是"我该怎么写"，不是"模型该生成什么"。
这些卡的 `实测: 待测` 是**永远填不上的死字段**，会让实测率永远到不了 100%。

**临时处置**：这 8 张的 `实测` 已改为 `不适用（方法类）`，实测率分母修正为 49。

**真问题未解**：方法类卡**应该怎么验**？候选口径——
- 用过没有（这条规则在写某份提示词时真的被援引了吗）
- 用了之后下游有没有变好（但下游变好是多因的，归因难）

**候选方案**：frontmatter 增 `验证方式: 模型服从 | 写作援引 | 双重`，`实测` 按类型分别记。
**按纪律 8 挂起**，等第二次触发或第一轮实测跑完后再定——**因为跑完才知道"模型服从"这一类到底怎么记，才好设计另一类。**


## ⏸ 待办 #2：全库站点标注复核（2026-08-13 登记）

纪律 7 立于 Framed Ink 第一批之后。**此前 57 张卡的 `站点` 是按旧口径（"会用到"）标的**，可能同样存在撑虚。

## 十二、v0.6：卡不等于门（2026-08-13）

**实证**：[[BODY-43 从剧本挖形体线索的四问]] 的失败模式写着侯寄南原话「**切忌拿到剧本后，只顾自己将要扮演的角色或几个重场戏**」。
我有这张卡，**并且照样只读了两场戏就定了九个构图决策**。通读全片后，三个关键决策里**错了两个**。

> **纪律 12：一张卡如果规定的是「开工前必须做什么」，它必须同时在路由表里成为一道门禁，而不只是一张卡。**
> 判据：卡的内容是**前置条件**（"必须先…才能…"）而非**执行规则**（"做X时应该Y"）→ 立门禁。
> 门禁必须有 **file artifact 判据**（`ls` 得出某个文件），不接受"我记得读过"。

**已立的门禁**：分镜 skill 站 −1「全片通读」→ 产出《全片约束表》。

**已复核（2026-08-14 · 待办 #4 结案）**：三张候选卡逐个过判据，**只有一张该立门禁**。

| 卡 | 判定 | 处置 |
|---|---|---|
| [[BODY-39 全形先于细部]] | ✅ **立门禁** —— 「**配角也要有全形**」是可数的覆盖性要求 | 站 0 门禁判据①：**形体卡人物数 == 台本有名字的人物数** |
| [[BODY-33 形体模型必须清晰]] | 🟡 **不另立** —— 它是**站 0 这一站本身的存在依据**，站已经在了。但缺一条"清晰"的判据 | 站 0 门禁判据②：**七个必填栏无空缺，不许留「待定」** |
| [[FRAME-42 先定戏核再定画面]] | ⚪ **不另立** —— **已被双重覆盖**：站 −1《全片约束表》有「逐场戏核」栏，站 7 出审阅版第一条必含项就是戏核 | 无需动作，登记即可 |

> **元教训**：「前置条件性质的卡」**不等于**「都要变成新门禁」。三种归宿：
> ①**立新门禁**（有可数判据且当前无人管）②**加进已有门禁的判据**（站已存在，缺的是判据）③**确认已覆盖**（别重复立门禁，那会造出走过场的关卡）。

> **纪律 13：限制类字段「空」是一个有意义的取值，不是「待填」。**（2026-08-14 立）
> 判据：一个字段如果记的是**限制**（"只有满足 X 才适用"），那么**空 ＝ 无限制**，是正确的终态。
> **不许因为「填充率低」就去补齐它**——那会把"无限制"错误地改成某个具体值，反而缩小卡的适用面。

**实证**：`适用场景类型` 填充率 13/106。我一度判定「88% 没填，要补 93 张」。
查已填的 13 张才发现——**全部是「≥2 人才适用」的限制标记**，从来不是分类。
**空着的 93 张是"这张卡单人戏也用得上"，本来就该空。**

| 字段 | 性质 | 空的含义 |
|---|---|---|
| `适用场景类型` | **限制** | 无人数限制 ✅ |
| `前置条件` | **限制** | 无项目级前置 ✅ |
| `可反用` | 限制 | — |
| `失败模式` · `站点` · `型` | **必填** | ⚠️ 缺失是缺陷 |
| `实测` | 状态 | ⚠️ 应写「待测」不留空 |

**配套动作**（限制类字段的正确维护方式）：
1. **统一词表**——同义值必须归一。实证：`[对话, 多人同场]` / `[多人同场, 对话]` / `[双人对话, 多人对话]` 三种写法指同一件事，已由脚本规范化
2. **找漏标**——按内容关键词反查"该标却没标"的卡。实证：[[FRAME-18 跨镜的强弱关系由三个对比建立]] 内容是"两个镜头拍两个人"，全库涉多人关键词命中最高，却漏标
3. **索引显式区分**——空值在索引里显示为 `无限制`，不显示为 `—`。**`—` 会被读成"没填"**

> **元教训**：填充率是个**信号**，不是**判据**。看到低填充率先问"这个字段的语义是什么"，再决定要不要补。

14. ⭐⭐ **抽卡前必须先查已有卡是否覆盖**——`grep -l "<关键词>" 卡/*.md`。
   　理由：**同一作者的不同书会重复讲同一套材料**。实证（2026-08-14）：
   　《场景透视》第十章「镜头」与已有的 [[FRAME-09 焦距决定景深与畸变]]（出自同一作者的 Framed Ink 1 第二章）
   　**内容高度重合，连「广角 1/5、长焦 15 倍」这两个数字都一模一样**。
   　若不先查就抽，会建出一张重复卡。
   　⭐ **正确处置**：重合部分登记为**跨书印证**（双向），只有**真正新增的层**才成卡——
   　该章 p.189/p.191 讲的是**叙事后果**（主次消失／符号化），FRAME-09 讲的是**光学原理**，**两层不是两遍**。

15. ⭐ **批次状态必须区分「已扫」与「部分精读」。**
   　按关键词密度定位热点页后只读热点，是合法的扫描策略（**精准补口**优于盲扫），
   　但**必须如实标 `部分精读`，并在批次文件里列出「已读部分」与「未读部分」的页码范围**。
   　⚠️ **不许**因为出了卡就标「已扫」——那会让索引的批次进度失真，
   　也会让下次的人以为这批读完了，永远不再回来。
